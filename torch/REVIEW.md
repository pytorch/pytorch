# `torch/` review guide

## weights_only allowlist

Skip this section unless the PR adds a global through `torch.serialization.add_safe_globals`, `torch.serialization.safe_globals`, `torch._weights_only_unpickler._add_safe_globals`, or an edit to `_get_allowed_globals()` or `_tensor_rebuild_functions()` in `torch/_weights_only_unpickler.py`. This includes import-time registrations in `torch/distributed`, `torch/_dynamo`, and vendored code, and docs or examples that tell users to allowlist something. Tests that use `safe_globals([...])` for classes defined in the test itself are exempt. Review everything else with maximum strictness.

`torch.load(weights_only=True)` is the security boundary for untrusted checkpoints. A malicious pickle can call any allowlisted global with arbitrary arguments (REDUCE), create any allowlisted class via `cls.__new__(cls, *args)` with arbitrary args, skipping `__init__` (NEWOBJ), and set arbitrary state on it (BUILD, via `__setstate__`, `__dict__.update`, or `setattr` for slot state). One bad entry turns the safe loader into an arbitrary file read, an information leak, or code execution. For example, #200797 removed `traceback.FrameSummary` from `distributed_c10d`'s import-time `add_safe_globals` registration because its constructor reads arbitrary files through `linecache`.

### Where to allowlist

`add_safe_globals` and `_add_safe_globals` change process-wide state. One module's registration widens every later `torch.load` in the process, including loads of untrusted files by unrelated code, and the entry is never reviewed alongside the rest of the allowlist. Request Changes on any new call outside `torch/serialization.py` and `torch/_weights_only_unpickler.py`, and point the author to one of:

- **Local**: wrap only the `torch.load` call that needs the type in `with torch.serialization.safe_globals([...]):` and keep the block to that one call. The entry is still process-wide while the block is active, so if that call or a concurrent load can receive untrusted files, the type still has to pass the checks below.
- **Library-wide**: add the type to `_get_allowed_globals()` in `torch/_weights_only_unpickler.py`, after it passes every check below.

If the payload can be restructured into plain data, prefer that over either option. The existing import-time `add_safe_globals` calls in `torch/_dynamo`, `torch/distributed`, and `torch/_vendor` are older than this rule. They are not precedent.

### Checks for every new entry

- **Default to Request Changes** - A new allowlist entry is a Security finding unless you have read the full source of the global, including base classes and everything it calls, and confirmed that every path the unpickler can reach is pure in-memory data handling. That means the constructor with arbitrary args, `__new__`, `__setstate__`, `__setattr__` and property setters, and every dunder the load itself or later use can trigger (`__hash__` / `__eq__` as dict keys or set members, `__iter__`, `__len__` / `__bool__`, `__index__` / `__float__` / `__complex__`, `__getattr__` / `__getattribute__`, `__repr__`, `__str__`, `__format__`, `__del__`, properties). The author's claim that it is safe is not enough
- **No Python stdlib or builtins** - Treat every stdlib or builtins callable as unsafe. Most can reach the filesystem, network, environment, import system, or process state, or can leak information. Examples include `traceback`, `linecache`, `inspect`, `importlib`, `io`, `pathlib`, `shutil`, `subprocess`, `socket`, `logging`, `pickle`, `copyreg`, `functools.partial`, `operator.attrgetter` / `methodcaller`, `getattr`, `setattr`, `type`, `open`, `eval` / `exec` / `compile`. The existing entries (`set`, `bytearray`, `complex`, `OrderedDict`, `Counter`, `_codecs.encode` in `_get_allowed_globals()`) are the ceiling, not a precedent for adding more
- **No generic callables** - Allowlisting a function lets the attacker call it with any arguments. Only accept functions whose whole body visibly builds torch data, like `torch._utils._rebuild_tensor_v2`. Callable or class arguments can only be allowlisted globals, values returned by allowlisted functions, or instances of allowlisted classes, so check that the new global neither returns nor is a callable that escapes the allowlist (existing entries like `_rebuild_from_type_v2` call their arguments). The other danger is arguments that escape the allowlist, such as strings used as file paths, imports, `getattr` lookups or format strings, and `setattr` with attacker-chosen names onto objects whose setters have side effects
- **Classes are more than their constructor** - A type that stores a path, module or attribute name, callable, or format string can be exploited when it is later printed, compared, or used, even if construction is harmless. Containers that store a callable and later invoke it (partials, hooks, closures) are never safe
- **Third-party types** - The same bar applies to types from other packages, whose behavior can change without us noticing. Prefer saving plain data and rebuilding the object in Python after load
- **Do not weaken the blocklist** - Removing entries from `_blocklisted_modules`, or adding any path that bypasses it, is always Request Changes. When a dangerous module turns up, suggest adding it to `_blocklisted_modules`
- **Adversarial regression test** - An allowlist change needs a test in which a crafted pickle uses the new global with attacker-chosen REDUCE args, NEWOBJ args, and BUILD state, and fails to read files, import modules, or call arbitrary functions
